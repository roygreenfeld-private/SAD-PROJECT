# Working Guidelines

Rules for everyone working on this project, including AI assistants.
If a rule here conflicts with the course syllabus or a Moodle instruction, the syllabus and Moodle win.

## Working rules
1. Language: all files, commit messages, and diagrams are in English.
2. Folder discipline: each file lives in the folder of its part and type (`documents`, `mcps`, `images`, `work-process-docs`).
3. Work on one part at a time. Do not start part B content before part A is submitted, except for notes.
4. Never invent facts about the organization. Every claim comes from an interview, observation, or a course-provided source. Mark unknowns as `[TBD]`.
5. Traceability: every user story links to a requirement, every use case to a requirement, every state transition to a business rule. Use the same IDs everywhere (FR-1, US-1, BR-1).
6. File names: lowercase, words separated by hyphens (`use-case-diagram.png`). No spaces.
7. Diagrams are stored both as source files and as exported images (in `images`).

## Using AI tools
1. Any AI use must be declared with the course's AI declaration form. Log each use in the part's `work-process-docs/ai-usage-log.md`: tool, purpose, and how the output was used.
2. The team is fully responsible for correctness. Every AI output is reviewed by a team member before it is committed.
3. When using AI, ask what it missed and what it assumed without saying.
4. AI does not decide business rules. The team decides, based on the interviews.

## Git rules
1. Commit small and often, one topic per commit, with a clear message (`Add BPMN for order process`).
2. Pull before you start working and push when you finish.
3. Do not edit another member's file without telling them.
4. Do not commit credentials, personal data, or interview recordings.

## Before every submission
- [ ] All IDs are consistent across documents
- [ ] No `[TBD]` left
- [ ] Names and ID numbers on the files, as required
- [ ] AI declaration form attached
- [ ] Final files open correctly and are in the right folders
